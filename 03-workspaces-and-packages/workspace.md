# Workspaces

A **workspace** is a folder where you develop, build, and install your own ROS 2 packages. Every ROS 2 project you work on lives in one. This lesson explains how a workspace is laid out, how to create and build one, and the single most important habit in ROS 2: **sourcing**.

## Topics Covered

- Workspace layout (`src`, `build`, `install`, `log`)
- Creating and building your first workspace
- Sourcing the setup files
- Underlay and overlay
- Installing dependencies with `rosdep`
- Cleaning a workspace

---

## Workspace Layout

A workspace starts as a folder with a `src` subfolder. After the first build, three more folders appear:

```text
~/ros2_ws/
├── src/        ← your source code: one folder per package (you edit this)
├── build/      ← intermediate build files (generated)
├── install/    ← built packages, ready to run (generated)
└── log/        ← build logs (generated)
```

| Folder | Contents | Edit it? | Commit to Git? |
|--------|----------|----------|----------------|
| `src/` | Package source code | ✅ Yes | ✅ Yes |
| `build/` | Temporary build files | ❌ No | ❌ No |
| `install/` | The result of the build, including `setup.bash` | ❌ No | ❌ No |
| `log/` | Output of every build | ❌ No | ❌ No |

You only ever work in `src/`. The other three can be deleted at any time and regenerated by building again (see [Git Basics](../00-prerequisites/git-basics.md#a-gitignore-for-a-ros-2-workspace) for the matching `.gitignore`).

> 📝 `ros2_ws` is only a convention. You can name a workspace anything and have several, for example one per project.

## Creating Your First Workspace

```bash
$ source /opt/ros/jazzy/setup.bash
$ mkdir -p ~/ros2_ws/src
$ cd ~/ros2_ws
```

Build it, even though it is still empty. Always run `colcon build` from the **workspace root**, never from inside `src`:

```bash
$ colcon build
Summary: 0 packages finished [0.21s]
```

If `colcon` is not found, install it:

```bash
$ sudo apt install python3-colcon-common-extensions
```

The folders `build`, `install`, and `log` now exist:

```bash
$ ls
build  install  log  src
```

## Sourcing the Workspace

Building puts your packages into `install/`, but ROS 2 does not know about them yet. To use them, **source** the workspace's setup file:

```bash
$ source ~/ros2_ws/install/setup.bash
```

This adds the workspace's packages to the environment of the **current terminal**, so `ros2 run` and `ros2 launch` can find them.

> ⚠️ **The most common beginner mistake:** forgetting to source the workspace in a new terminal, or after building a new package. The symptom is `Package 'my_first_pkg' not found`. When in doubt, source again.

You can add the line to `~/.bashrc` so every new terminal is ready, **after** the line that sources ROS 2 itself:

```bash
source /opt/ros/jazzy/setup.bash
source ~/ros2_ws/install/setup.bash
```

> 💡 Do not source a workspace in the same terminal you build it in, if you can avoid it. Use one terminal for building and another for running. Building in a terminal that has the workspace sourced works, but can cause confusing results when packages are removed or renamed.

### `setup.bash` vs `local_setup.bash`

The `install/` folder contains two setup files:

| File | Sources |
|------|---------|
| `setup.bash` | This workspace **and** the underlay it was built on (for example `/opt/ros/jazzy`) |
| `local_setup.bash` | **Only** this workspace |

Use `setup.bash` unless you have a specific reason not to.

## Underlay and Overlay

Workspaces stack on top of each other:

```text
┌─────────────────────────────┐
│  ~/ros2_ws        (overlay) │  ← your packages
├─────────────────────────────┤
│  /opt/ros/jazzy  (underlay) │  ← ROS 2 installed with apt
└─────────────────────────────┘
```

- The **underlay** is the environment that was sourced when you built: usually the ROS 2 installation in `/opt/ros/jazzy`.
- The **overlay** is your workspace, built on top of it.

If both contain a package with the same name, **the overlay wins**. This is useful: to fix a bug in an installed package, clone its source into your workspace's `src`, change it, and build. Your version now replaces the installed one, without touching `/opt/ros`.

You can stack more levels (a team workspace on top of ROS 2, your personal workspace on top of that), but keep it simple while learning.

## Installing Dependencies with `rosdep`

Packages you clone from the internet often depend on other packages that are not installed yet. **`rosdep`** reads the dependencies listed in each package's `package.xml` and installs them with `apt`.

One-time setup:

```bash
$ sudo apt install python3-rosdep
$ sudo rosdep init
$ rosdep update
```

Then, from the workspace root, whenever you add packages to `src`:

```bash
$ cd ~/ros2_ws
$ rosdep install --from-paths src --ignore-src -y
#All required rosdeps installed successfully
```

| Option | Meaning |
|--------|---------|
| `--from-paths src` | Check all packages found in `src` |
| `--ignore-src` | Don't try to install packages that are already in `src` |
| `-y` | Answer "yes" to installation prompts |

You will learn how to declare dependencies in [package.xml](package-xml.md).

## Example: Building Packages from Source

Let's put it all together by building the turtlesim source code in your workspace:

```bash
$ cd ~/ros2_ws/src
$ git clone https://github.com/ros/ros_tutorials.git -b jazzy
$ cd ~/ros2_ws
$ rosdep install --from-paths src --ignore-src -y
$ colcon build
Starting >>> turtlesim
Finished <<< turtlesim [25.3s]

Summary: 1 package finished [25.6s]
```

In a **new terminal**:

```bash
$ source ~/ros2_ws/install/setup.bash
$ ros2 pkg prefix turtlesim
/home/utku/ros2_ws/install/turtlesim
```

`ros2 pkg prefix` now points to your workspace instead of `/opt/ros/jazzy`: the overlay wins. You could change the turtlesim code, rebuild, and run your own version.

> 📝 The `ros_tutorials` repository may contain more packages than turtlesim, depending on the branch. colcon builds every package it finds in `src`.

## Cleaning a Workspace

To rebuild everything from scratch, delete the generated folders and build again:

```bash
$ cd ~/ros2_ws
$ rm -rf build install log
$ colcon build
```

When to clean:

- After deleting or renaming a package (old files stay in `install/` otherwise).
- When a build behaves strangely and you can't explain why.
- After switching to a different ROS 2 distribution.

> ⚠️ Double-check that you are in the workspace root before running `rm -rf`. Never delete `src`.

To clean up after the example above, remove the cloned turtlesim so the installed version is used again:

```bash
$ rm -rf ~/ros2_ws/src/ros_tutorials
$ rm -rf ~/ros2_ws/build ~/ros2_ws/install ~/ros2_ws/log
$ colcon build
```

## Try It Yourself

1. Create a second workspace `~/test_ws` with an empty `src` folder and build it. Which files are in `install/`?
2. Open a new terminal **without** sourcing ROS 2 and run `ros2`. Then source only `~/ros2_ws/install/setup.bash` (not `/opt/ros/jazzy`). Does `ros2` work now? Why?
3. Run `printenv AMENT_PREFIX_PATH` before and after sourcing your workspace. What changed?
4. Clone `ros_tutorials` into your workspace as shown above, build it, and check with `ros2 pkg prefix turtlesim` that your overlay is used. Then clean it up again.
